## 1. 产品定位

### 1.1 一句话

课旁是一个「微信客服助手 + 微信小程序」：把班群里的通知长按转发给助手，自动识别成**日程**或 **DDL**，和课表放在同一屏；课表从聊天记录里的 Excel/PDF/图片导入，日程叠加在对应时间块，DDL 进入“本周 DDL”栏，并叠加在对应时间块。

### 1.2 产品形态

- **入口侧**：微信客服助手。主入口是长按群里的单条消息，转发给课旁客服会话；也可以直接在客服会话输入单条文字作为兜底。两种方式都不需要加好友。
- 
- **使用侧**：微信小程序。承载课表、日程、DDL、任务、导入、确认和设置。
- **服务端**：接收微信客服回调，拉取消息内容，调用规则 + 大模型抽取，返回确认卡片。
- **第一版不做独立 App**，也不做 iOS/Android 原生客户端。

### 1.3 定位边界

- 不做“又一个课表 App”。课表是底座，不是卖点；课表导入在 2025–2026 年已是行业标配。
- 不做社区、树洞、广告、成绩查询、GPA 计算、番茄钟、打卡。
- 不做全量教务系统对接。最多做少量标杆学校，主要靠文件导入和手动添加。
- 不在第一版承诺“长期自动提醒”。订阅消息按一次性额度设计，额度用完后的兜底是小程序内的“本周 DDL”栏。
- 不在第一版做合并转发、图片通知识别、图片课表导入。这些要等真机和准确率验证后再放开。
- 不在第一版做多轮聊天式记录、对话记忆或多条消息合并；直接输入只处理单条文字。
- 不读取微信/QQ 聊天记录，不后台监听剪贴板，只处理用户主动转发、直接输入、复制或上传的内容。

### 1.4 价值主张

对用户，价值是把“看到通知 → 手动拆时间地点 → 切换工具记录”压缩成“长按转发 → 核对卡片 → 存进课表旁边”。

对场景，价值是把“要去参加的活动”和“必须在某时前完成的 DDL”分开呈现，而不是都塞进一个任务清单。

对信任，价值是识别结果可核对、可修改、可撤销；第一版不自动写入正式数据。

## 2. 目标用户

### 2.1 目标用户

在校大学生，优先本科大二、大三，满足至少两条：

- 每周 10 节以上课程；
- 参加社团、学生会、志愿活动，需要记会议、活动、面试、答辩；
- 经常在班群、学院群、课程群收通知；
- 过去一个月至少 3 次需要记录课程以外的安排；
- 目前用学校官方课表小程序加备忘录/日历，信息分散在两个以上工具里。

### 2.2 非目标用户

- 几乎不参加课程外活动、不需要记录通知的学生；
- 主要需求是社区、成绩、社交、广告的学生；
- 非在校学生；
- 需要完整教务系统深度对接的学校或机构（第一版不做）。

### 2.3 用户画像（基于 06，初步）

**高频记录者。** 过去一个月 6–10 次需要记录课程外安排，会主动记到课表工具或备忘录。对“少点几次、少切一个工具”敏感，是 MVP 的首要用户。

**低介入者。** 过去一个月 1–2 次，收到通知只看一眼、靠脑子记或截图。短期不是重点用户，但可能被“转发一次就存”的轻动作转化。

06 只有 2 份问卷和 1 份访谈，以上画像是方向性的，不是统计结论。目标人群比例需要在问卷补样后确认。

### 2.4 使用场景

1. 班群通知：“周四下午 3 点在 A301 开年级会，带学生证” → 长按转发 → 识别成日程 → 确认保存。
2. 作业/材料：“下周五前把数据结构实验报告发我邮箱” → 转发 → 识别成 DDL → 进入本周 DDL。
3. 考试、报名、讲座、志愿活动 → 转发 → 识别成日程或 DDL。
4. 开学导入课表：从聊天记录选 Excel/PDF/图片 → 预览 → 修正 → 保存。
5. 课前或当天查看：课表为底，日程叠加在时间块，DDL 在顶部待办栏。

## 3. 用户问题与现有替代

### 3.1 用户问题

**P1 固定时间段限制。** 学校课表只能按固定上课时间段添加日程，会议、讲座、志愿活动、面试不好放，时间粒度也不够。状态：竞品研究判断为半成立；06 的访谈没有直接验证，待补充。

**P2 群通知手动提取。** 通知里通常包含时间、地点、活动名，用户要自己从长文字里拆出来，再填进另一个工具。状态：竞品研究认为成立且被低估；06 部分支持（R1 会记到课表工具，访谈认为转发识别省了手动记录）。

**P3 DDL 与日程混在一起。** 作业、报名、交材料是“某时前完成”，会议、答辩、活动是“某时参加”，两类事混在任务清单里容易漏。状态：竞品研究认为成立；06 未证实，一人分开管理、一人不区分且没有报告混乱。按待验证处理。

**P4 课表与日程不同屏。** 查看课表和查看日程要来回切工具。状态：06 中 2/2 选“比较希望”同屏，方向成立，但强度不高。

**P5 清理成本。** 现有课表工具的过期任务要一周一周删，学期切换时残留多。状态：访谈中冒出的新问题，06 的问卷没有覆盖。

**P6 工具分散。** 官方课表、备忘录、日历、微信收藏各管一部分，用户靠定期翻看而不是靠工具提醒。状态：访谈证据。

### 3.2 现有替代方案

| 替代方案 | 用户怎么做 | 不足 |
|---|---|---|
| 学校官方课表小程序/教务系统 | 教务系统一键导入课表；在固定时间段添加日程 | 时间粒度受限；清理任务麻烦；日程和 DDL 不区分 |
| 手机自带日历/备忘录 | 手动建事件、打勾、定期清理 | 没有课表语境；和课表分开看；不会从群通知自动提取 |
| 超级课程表/WakeUp 等课表 App | 教务导入 + 课表 + 社区 | 广告、社区噪音、加载慢；非课程日程能力弱 |
| 滴答清单/Todoist | 任务清单、日历视图、微信助手 | 不识别地点；不区分日程与 DDL；没有节次/单双周语境 |
| 截图、纸质课表、微信收藏、文件传输助手 | 截图保存、收藏、靠记忆 | 不可检索、不可提醒、容易漏 |
| 只看一眼，靠脑子记 | 不进入任何工具 | 短期省事，长期容易漏 |

竞品研究里有一个判断：真正的替代对象不一定是另一个 App，而是“群通知 + 记忆”。课旁要替代的是这套松散流程，不是某一个具体产品。

### 3.3 研究证据与假设状态

| 假设 | 当前证据 | 状态 |
|---|---|---|
| H1 固定课表时间段限制添加非课程日程 | 竞品研究半成立；访谈未直接提到时间段限制 | 待验证 |
| H2 学生经常收到需要记录的通知 | R1 每月 6–10 次，R2 每月 1–2 次；两人都漏过通知 | 部分支持 |
| H3 从长消息手动提取时间/地点/活动是负担 | R1 记到课表工具；访谈认为转发能省手动记录；没有耗时数据 | 部分支持 |
| H4 DDL 与日程混合造成混乱 | 06 未证实；竞品研究认为成立 | 待验证 |
| H5 希望课表与日程同屏 | 2/2 选“比较希望” | 初步支持 |
| H6 文件导入降低建表成本 | 访谈对象从教务系统导入很顺利；导入已是行业标配 | 不构成差异化 |
| H7 长按转发自动提取减少手动录入 | 访谈概念上认可；没有真实使用数据 | 概念支持 |
| H8 日程/DDL/任务分类与视觉区分提高理解 | 访谈认为红色 DDL 有用；R2 自己不区分 | 部分支持 |
| H9 用户愿意在识别后确认或修改 | R1 明确不愿确认；R2 接受 20 秒内；访谈接受核对但担心准确率 | 与假设冲突，需测试 |
| H10 愿意为识别群通知额外使用微信客服助手 | Q11 一人“一般”、一人“比较愿意”，无“非常愿意” | 谨慎支持 |

完整证据见 [06-研究发现](../06-研究发现/研究发现.md)。

## 4. 竞品与差异化

### 4.1 竞品画像

**超级课程表。** 对接 500–1500 所高校，App Store 评分 2.9–3.0，差评集中在开屏/震动广告、课表加载慢、社区内容。存在“工具纯净”的替代空间，但它的课表导入和教务覆盖是硬壁垒。

**滴答清单 TickTick。** 国内版约 ¥138/年（Android）、¥168/年（iOS）。支持微信转发给“滴答小助手”创建任务、识别日期时间，AI 语音可拆多条任务；但不识别地点，不区分日程与 DDL，把课表当普通事件塞进通用日历。它的“小助手”是扫码添加的微信好友，不是小程序。

**新入局课表 App。** 易课表、SleepDown、Meet、准点课表等已经把图片/PDF/教务导入、预览确认做成标配；SleepDown 明确“生成后先进入预览页再确认”。准点课表、课程表 ToDo 开始区分课程/作业/考试。单个产品小而全，但都没有做“群通知 → 日程/DDL”的完整链路。

### 4.2 差异化

1. **从一条群通知里抽取地点。** 滴答清单只识别日期时间，不识别地点；课表 App 只解析课表网格，不解析群通知。这是竞品研究里最明确的空白。
2. **自动区分日程、DDL、任务。** 不是让用户自己选类型，而是识别后给出类型，用户可改。视觉上分开：日程是时间块，DDL 是截止条，任务是可勾选准备项。
3. **课表为底、日程/DDL 为层的一屏视图。** 竞品要么把课表当普通事件，要么把课表 and 日程分标签。同屏本身是基础体验，不单独当卖点。
4. **微信内原生长按转发。** 用户不需要离开微信，不需要加好友。但“多开一个客服会话”的接受度还没验证，这是 H10 的风险。
5. **工具纯净。** 不做社区、不做广告、不做成绩查询，只做“课表旁边的安排”。

### 4.3 不构成差异化的能力

- 课表导入：Excel/PDF/图片/教务导入已是标配，只作为入场券。
- 识别后预览确认：SleepDown、Huawei AI 课表等已经在做，是设计原则，不是卖点。
- 课表与日程同屏：系统日历、部分课表 App 已能部分满足，是基础体验。
- 提醒：订阅消息额度有限，不能承诺长期自动提醒，不能当核心卖点。

## 5. MVP 范围

### 5.1 必做

| 模块 | 范围 | 验收标准 |
|---|---|---|
| 微信客服接待 | 企业微信客服，用户可通过链接/二维码进入；M0 验证期设“仅人工”做 Concierge 验证，正式 MVP 接客服回调 + AI 抽取 | 用户可以长按单条消息转发给客服会话，也可以直接在会话输入单条文字；会话可找回或提供永久入口 |
| 客服回调服务 | 验签、`sync_msg` 拉取、`send_msg` 回复、按 `msgid` 幂等、持久化 cursor、失败补偿 | 回调 5 秒内返回；消息不丢不重；3 天内可补偿拉取 |
| 文字通知识别 | 转发或直接输入的单条文字；先判断是否包含可记录事项；标题、时间、地点、类型（日程/DDL/任务/未知）、多事件拆分、置信度、证据片段 | 见 5.3 的识别门槛；闲聊/问用法不生成记录；结果以确认卡片返回 |
| 确认页 | 所有字段可编辑；低置信度字段标“请确认”；保存/取消；不自动写入 | 用户核对后写入对应表；取消不产生数据 |
| 小程序首页 | 课表为底，日程叠加时间块，DDL 进入本周栏，逾期标红，任务可勾选 | 首屏可切换周次；日程与 DDL 视觉可区分 |
| 课表导入 | 从微信聊天记录选 Excel/CSV、文字型 PDF；预览确认后保存 | 课程数准确率 ≥90%；字段准确率 ≥80%；30 秒内完成 |
| 手动创建 | 手动添加课程、日程、DDL、任务 | 无网络/识别失败时可完成主流程 |
| 剪贴板兜底 | 用户点击后读取剪贴板识别；不后台监听 | 只在用户主动点击时触发；有明确提示 |
| 直接输入兜底 | 用户在客服会话直接输入单条文字，走同一识别链路；先做意图判断 | 只处理包含事项的单条文字；信息不全时追问或引导手动创建，不猜测 |
| 订阅消息 | 一次性订阅额度；用户主动点击后发送；额度不足时小程序内提示 | 不承诺长期自动提醒；文案不夸大 |
| AI 标注 | 结果页固定显示“AI 整理，请核对” | 不删除平台 AI 标识 |
| 反馈入口 | 反馈分类、错误类型、严重度、状态 | 用户可提交；团队每周看错误分布 |

> 注：表中的“仅人工”只用于 M0 的 Concierge/Wizard-of-Oz 验证，不是正式产品形态。正式 MVP 的识别由 AI 完成，用户核对后才写入课旁；识别字段是标题、时间、地点、类型，不包含“人物/负责人”。

### 5.2 暂不做 / 黑名单

- 独立 App、iOS/Android 原生客户端。
- 读取微信/QQ 历史聊天记录；后台监听剪贴板。
- 合并转发解析（待真机验证；结果出来前不承诺）。
- 图片通知 OCR（第一版先做文字，图片放 v0.2）。
- 图片/拍照课表导入（先做 Excel/CSV 和文字 PDF；OCR 准确率达标后再开）。
- 全量教务系统对接（最多做少量标杆学校）。
- 社区、树洞、下课聊、CP 匹配、跨院系蹭课。
- 开屏广告、信息流广告、广告变现。
- 成绩查询、GPA 计算。
- 番茄钟、专注、打卡、学习统计。
- 免费版内支付/订阅（后续单独做合规）。
- 自动把识别结果写入正式数据（必须用户确认）。
- 多轮聊天式记录、对话记忆、多条输入消息合并（第一版只做单条文字）。
- 长期自动提醒承诺。
- 个人号机器人、外挂、插件、非官方接口。

### 5.3 MVP 验证门槛

| 指标 | 门槛 | 不达标怎么办 |
|---|---|---|
| 事件级完整正确率 | ≥80% | 收窄到“时间 + 标题”，地点/类型降级 |
| 时间识别准确率 | ≥90% | 低置信度字段强制确认 |
| 地点识别准确率 | ≥80% | 地点放二期，或标记“请确认” |
| 类型识别准确率 | ≥85% | 第一版让用户手动选类型 |
| 幻觉率 | <5% | 不自动写入，全部确认 |
| 多事件召回率 | ≥80% | 引导用户分次转发，确认页可删除多余项 |
| 识别延迟 P95 | ≤5 秒 | 优化模型/规则；超时给兜底 |
| 单条识别成本 | ≤0.05 元 | 规则优先、缓存、降级小模型 |
| 确认中位时长 | ≤10 秒/条 | 简化字段；测试“高置信度直接存 + 撤销” |
| 修改率 | ≤30% | 分析错误类型，改 prompt/规则 |
| 课表课程数准确率 | ≥90% | 只支持 Excel/文字 PDF；图片导入延后 |
| Concierge 验证 | ≥6/10 用户愿意连续用 3 次以上 | 不投入 AI 开发，回到需求验证 |

## 6. 核心用户流程

### 6.1 首次使用

1. 用户扫描客服二维码或点客服链接，进入课旁客服会话。
2. 客服发送欢迎语和小程序入口，说明“只处理你主动转发、直接输入或上传的内容”。
3. 用户打开小程序，完成隐私政策与必要授权。
4. 用户导入课表（从聊天记录选文件/手动添加）或先跳过。
5. 用户看到空白课表，引导“转发一条群通知试试，也可以直接输入要记的事”。

### 6.2 日常：转发或直接输入

1. 用户在班群长按一条通知，选择“转发”。
2. 选择课旁客服会话，发送。
3. 服务端收到回调事件，用 token + cursor 调 `sync_msg` 拉取正文。
4. 预处理：文本清洗；规则预抽取日期、时间、地点、截止词；大模型输出结构化 JSON；校验日期、年份、地点、类型、置信度。
5. 客服回复一张确认卡片（或小程序卡片），显示标题、时间、地点、类型、置信度。
6. 用户点开确认页，核对/修改字段。
7. 用户点“保存”，数据写入日程、DDL 或任务表。
8. 首页课表刷新，日程叠加到时间块，DDL 进入本周栏。

**直接输入（兜底）。** 用户也可以不转发，直接在客服会话输入一条包含事项的文字，例如“周四下午 3 点 A301 答辩”。两种入口走同一套回调、预处理和抽取；所有输入都先做意图判断，直接输入尤其需要，因为可能只是闲聊或问用法：没有可记录事项的内容不进入抽取，回复使用说明或追问。第一版只处理单条文字，不合并多条消息、不做多轮上下文；信息不全时提示用户补全或手动创建。

### 6.3 查看与提醒

1. 用户打开小程序，默认显示本周课表。
2. 日程以时间块叠加在课表上，DDL 在本周 DDL 栏，逾期标红。
3. 任务清单可勾选，关联到日程或 DDL。
4. 用户点击日程/DDL 查看详情，可编辑、删除、标记完成。
5. 订阅消息额度可用时，用户可对某条 DDL 或日程授权提醒；额度不足时，产品只提示“打开小程序查看”，不承诺推送。

### 6.4 失败兜底

| 失败点 | 兜底 |
|---|---|
| 单条转发收不到完整内容 | 改为“复制消息 → 小程序点击读取剪贴板”；入口文案讲清楚 |
| 直接输入的内容信息不全 | 追问缺失字段；仍不完整则引导手动创建，不猜测 |
| 闲聊或问用法被误判为通知 | 先做意图判断；无事项时回复使用说明，不生成记录 |
| 合并转发不可解析 | 只承诺单条转发；多条引导分次转发 |
| 识别失败/置信度低 | 返回“没识别清楚”，让用户手动编辑或重新转发 |
| 多事件拆分错误 | 确认页可删除多余项、逐条编辑 |
| 课表文件解析失败 | 手动添加/重新上传；支持从微信聊天记录重选 |
| 订阅额度用完 | 小程序内“本周 DDL”栏兜底；进入小程序时提示补充额度 |
| 客服会话找不到 | 提供永久客服链接/二维码；不依赖聊天记录作为数据源 |

## 7. 页面清单与功能需求

### 7.1 页面清单

| 页面 | 作用 | 优先级 |
|---|---|---|
| 首次使用/引导 | 隐私同意、产品说明、入口引导 | P0 |
| 首页/课表页 | 课表为底，日程叠加，DDL 栏，任务 | P0 |
| 识别确认页 | 核对/编辑/保存识别结果 | P0 |
| 课表导入页 | 从聊天记录选文件、预览、修正 | P0 |
| 日程/DDL 详情页 | 查看、编辑、删除、完成 | P0 |
| 设置/隐私页 | 隐私政策、数据删除、订阅额度、账号 | P0 |
| 反馈页 | 提交错误/建议 | P1 |
| 空状态/加载/错误态 | 全局状态 | P0 |

### 7.2 首页/课表页

**目标：** 用户打开小程序，一屏看到本周课表、叠加日程和本周 DDL。

**元素：**

- 顶部：当前周次、左右切换、今天的日期。
- 课表区：周一至周日 × 节次网格；课程块显示课程名、地点、教师（可省略）。
- 日程层：一次性日程以不同颜色的时间块叠加在对应时间。
- 本周 DDL 栏：按截止时间排序；逾期红色；点击进入详情。
- 任务清单：关联日程/DDL 的准备项，可勾选。
- 添加按钮：手动添加日程/DDL/任务。
- 空状态：没有课表时显示“导入课表”和“手动添加”两个入口。

**交互：**

- 左右滑动切换周次；点击课程/日程/DDL 打开详情。
- 下拉刷新；首次进入加载骨架屏。
- DDL 逾期颜色与普通 DDL 区分；日程与课程颜色区分。

**状态：**

- 加载中：骨架屏，不跳布局。
- 空：没有课程/日程/DDL 时显示引导，不显示空白网格。
- 接口报错：显示“加载失败，重试”按钮；保留上次缓存数据（如果有）。
- 离线：显示离线提示，允许查看缓存。

**验收标准：**

- 首屏 P95 加载 ≤2 秒（缓存命中时 ≤500ms）。
- 切换周次不白屏；当前周次和日期正确。
- 日程与课程视觉可区分；DDL 逾期标红。
- 点击任意条目能进入详情；返回后状态保持。

### 7.3 识别确认页

**目标：** 让用户用最短时间核对识别结果，确认后才写入。

**元素：**

- 原始消息摘要（可折叠）。
- 字段：标题、日期、开始时间、结束时间、地点、类型（日程/DDL/任务）、截止时间（DDL）、准备事项（任务）。
- 每个字段旁显示置信度状态；低置信度标“请确认”。
- 类型切换：日程 / DDL / 任务。
- 操作：保存、取消、重新识别（可选）。
- 固定提示：“AI 整理，请核对”。

**交互：**

- 点击字段直接编辑；日期/时间用选择器；地点可手动输入。
- 保存后回到首页并高亮新条目；取消不写入。
- 多事件时，卡片分条展示，可删除多余项。
- 识别失败时，显示原文和手动创建入口。

**状态：**

- 加载中：显示“正在整理…”；超过 5 秒显示“还在处理，可以先手动填写”。
- 空/失败：显示失败原因和手动创建按钮。
- 接口报错：保留原文，允许重试。

**验收标准：**

- 所有字段可编辑；低置信度字段有明确标识。
- 保存后写入正确类型；取消后数据库无新增。
- 确认中位时长 ≤10 秒/条；修改率 ≤30%。
- 结果页始终显示“AI 整理，请核对”。

### 7.4 课表导入页

**目标：** 让用户从微信聊天记录里选课表文件，预览后保存。

**元素：**

- 入口：从聊天记录选择文件（Excel/CSV/PDF）、拍照/相册（后续）、手动添加。
- 文件预览：解析出的课程列表，按星期/节次展示。
- 字段：课程名、教师、地点、星期、起止节次、起止周、单双周。
- 操作：全选/取消、逐条编辑、删除、保存。
- 失败提示：哪一行/哪一列无法识别，允许手动补。

**交互：**

- 选择文件后显示解析进度；解析完成进入预览，不直接写入。
- 用户可以修改任意课程；保存后覆盖或合并当前课表（需确认）。
- 解析失败可重新选择文件或手动添加。

**状态：**

- 加载中：解析进度/骨架屏。
- 空：文件没有识别出课程时，显示“手动添加”与“重新选择”。
- 报错：文件过大/格式不支持/解析失败，分别给出提示。

**验收标准：**

- 支持 Excel/CSV 和文字型 PDF；单文件 ≤20MB。
- 课程数准确率 ≥90%；课程名/教师/地点 ≥80%；星期/节次/周次 ≥80%。
- 上传到确认 ≤30 秒（P95）。
- 保存前必须经过预览确认；不自动覆盖已有课表。

### 7.5 日程/DDL 详情页

**元素：** 标题、类型、日期时间、地点、来源消息摘要、创建时间、状态、关联任务。

**交互：** 编辑、删除、标记完成、复制、返回。

**验收标准：** 编辑后首页同步；删除有二次确认；DDL 可标记完成；日程可标记已参加/取消。

### 7.6 设置/隐私页

**元素：**

- 隐私政策、用户协议、第三方 SDK 列表。
- 数据删除入口：删除单条识别记录、清空日程/DDL、注销账号。
- 订阅消息额度状态与补充入口。
- 客服入口/帮助。
- 版本号、反馈入口。

**验收标准：** 注销账号后 15 个工作日内删除或匿名化；删除操作有确认；隐私政策可随时查看。

### 7.7 反馈页

**元素：** 反馈类型（识别错误/功能建议/其他）、原文（仅用户主动提交）、期望结果、截图（可选）、联系方式（可选）。

**验收标准：** 提交成功有回执；反馈进入后台分类；P0 错误 24 小时内响应（内测期）。

### 7.8 全局状态

| 状态 | 要求 |
|---|---|
| 加载中 | 骨架屏或明确的进度提示，不白屏、不跳布局 |
| 空 | 说明为什么空、下一步做什么，不显示无意义空白 |
| 接口报错 | 人话解释 + 重试按钮；保留可用的缓存数据 |
| 无网络 | 明确提示；可查看缓存；写操作排队或提示稍后重试 |
| 权限不足 | 说明需要什么权限、为什么；提供去设置入口 |

## 8. 数据模型

## 9. 技术方案与依赖

### 9.1 架构

```text
微信班群
  → 长按转发
  → 微信客服会话
  → 客服回调（只给事件 + token）
  → 服务端 sync_msg 拉取正文
  → 预处理（文本/OCR/文件解析）
  → 规则预抽取 + 大模型结构化 JSON
  → 校验（日期、年份、地点、类型、置信度）
  → 确认卡片 / 小程序确认页
  → 用户确认
  → 写入 schedule/ddl/task
  → 小程序首页展示 + 订阅提醒（额度内）
  → 失败兜底：复制粘贴 / 手动创建
```

### 9.2 技术栈

| 层 | 选择 | 说明 |
|---|---|---|
| 小程序 | 原生微信小程序（WXML/WXSS/JS/TS） | 第一版不引入 Taro/uni-app，减少构建复杂度 |
| 服务端 | Python FastAPI 单体 | 单人 MVP 优先；后续可拆分 |
| 数据库 | MySQL 或 PostgreSQL | 结构化数据 |
| 缓存/队列 | Redis | 回调补偿、限流、幂等 |
| 文件存储 | 对象存储 | 课表文件、图片；解析后按策略删除 |
| 大模型 | 国内模型（通义千问/DeepSeek/GLM 等） | 支持 JSON schema/function calling；境内部署、不训练、不留存 |
| OCR/解析 | 腾讯云/阿里云 OCR、PaddleOCR；openpyxl/pandas；pdfplumber/PyMuPDF | 解析放服务端，不放进小程序包 |
| 部署 | 阿里云/腾讯云 + HTTPS + 备案域名 | 小程序请求域名需备案并配置 |
| 监控 | Sentry/日志服务 | 不记录完整聊天正文 |

### 9.3 微信能力约束

| 能力 | 约束 | 对产品的影响 |
|---|---|---|
| 客服回调 | 只推送 `kf_msg_or_event` 事件和临时 token，正文需 `sync_msg` 拉取 | 必须实现 token + cursor 拉取、幂等、补偿 |
| 消息留存 | `sync_msg` 只保留最近 3 天 | 回调后立即落库；过期无法补拉 |
| 回调超时 | 5 秒超时，重试 3 次 | 立即返回、异步处理；防重复 |
| 出站额度 | 用户发消息后 48 小时内最多 5 条 | 欢迎语、卡片、提醒要省着用 |
| 订阅消息 | 一次授权一条；单次最多 5 个模板；长期订阅仅部分线下公共服务类目 | 不承诺长期自动提醒；额度分配优先 DDL |
| 媒体大小 | 图片 2MB、语音 2MB、视频 10MB、文件 20MB | 超限给提示；课表文件限制 20MB |
| 选文件 | `wx.chooseMessageFile` 只能从聊天记录选，单次最多 100 个 | 导入入口放在聊天记录场景 |
| 小程序包 | 主包 ≤2MB，单个分包 ≤2MB，总包 ≤30MB | OCR/表格解析库放服务端 |
| 客服入口 | 无自然发现路径，需链接/二维码；未认证企业微信累计 100 客户 | 冷启动靠班级群/海报；测试期不认证 |
| 身份 | 客服侧只有 `external_userid`；需绑定同主体小程序/开放平台或一次性 token 关联 openid | 订阅提醒触达依赖身份打通 |
| 类目/备案 | 建议“工具-日历”；小程序备案 + 域名 ICP 备案 | 上线前置，不能拖到开发后 |

### 9.4 AI 抽取

- 输入：用户主动转发或在客服会话直接输入的单条文字（第一版）；图片/文件/多条消息后续。
- 意图判断：先判断消息是否包含可记录事项；闲聊、问用法、无法识别的内容不进入抽取，返回帮助或追问。
- 输出 JSON：标题、日期、开始/结束时间、地点、类型（日程/DDL/任务/未知）、截止时间、准备事项、多事件数组、置信度、证据片段。
- 规则 + 模型：先用正则/规则抽日期、时间、地点、截止词，再让模型补全和结构化；模型输出必须通过 schema 校验。
- 失败处理：JSON 不合法重试一次；仍失败转人工/手动；低置信度字段标“请确认”。
- 评测：30 条真实通知标注，20 条留出集；至少 3 组模型/prompt 对比；温度 0–0.2；记录 token、延迟、成本。
- 版本：记录 `model_version`、`prompt_version`，便于回溯。

### 9.5 课表导入

- 第一版：Excel/CSV、文字型 PDF；解析后进入预览，用户确认后保存。
- 第二版：扫描 PDF、图片、拍照；OCR + 表格结构识别；准确率达标后再开。
- 解析放服务端；小程序只负责选择文件、预览和确认。
- 支持中国高校常见格式：第几节、起止周、单双周、合班课；解析失败给出行列级提示。

### 9.6 非功能目标

| 指标 | 目标 |
|---|---|
| 文字识别延迟 | P95 ≤5 秒 |
| 课表导入延迟 | P95 ≤30 秒 |
| 可用性 | 99.5%（MVP） |
| 单条识别成本 | ≤0.05 元 |
| 安全 | HTTPS、回调验签、防重放、幂等、限流、密钥管理 |
| 日志 | 不记录完整聊天正文；网络日志至少 6 个月 |

## 11. 隐私与合规

### 11.1 数据最小化

- 只处理用户主动转发、直接输入、复制或上传的内容；不读取聊天记录，不后台监听剪贴板。
- 转发或直接输入的内容会到达服务器用于识别，入口处必须明示，不能默认用户知道。
- 不保存原始聊天全文：识别完成后只保留结构化结果；原文按策略删除。
- 课表文件解析后删除；用户选择保存的课表才保留。
- 不收集与功能无关的聊天内容、通讯录、位置。

### 11.2 上线前 P0

1. 隐私政策、微信《用户隐私保护指引》、首次单独同意弹窗、第三方 SDK 列表。
2. 完成个人信息保护影响评估（PIA），覆盖第三方 LLM/OCR 委托处理。
3. 小程序 APP 备案 + 后端域名 ICP 备案；公网安备 30 日内。
4. 与 LLM/OCR/云供应商签数据处理协议，确认境内存储、不训练、不留存。
5. AI 结果固定标注“AI 整理，请核对”；接入微信内容安全接口。
6. 提供删除识别记录、删除数据、注销账号入口。
7. 不接支付；如后续接支付，单独做商户、类目、退款、发票、自动续费合规。
8. 涉及未成年人：14 岁以下需监护人同意；17 岁付费订阅需监护人同意/追认（后续支付阶段）。
9. 找执业律师复核生成式 AI/深度合成、第三方个人信息、校园合作等 8 个待确认问题。

### 11.3 数据留存

| 数据 | 留存策略 |
|---|---|
| 聊天原文/图片/文件 | 解析成功后立即删除；失败重试最多 24–72 小时 |
| 课表文件 | 解析后删除；用户选择保存的课表保留 |
| 结构化日程/DDL/任务 | 账号存续期间；注销后 15 个工作日内删除或匿名化 |
| 微信 openid | 账号存续期间 |
| 客服会话 | 按官方 API；不主动做会话存档 |
| 网络日志 | 至少 6 个月（法定）；不含聊天正文 |
| 用户反馈 | 建议 90 天内处理/删除 |
| 模型调用日志 | 关闭或 ≤7 天；不用于训练 |

### 11.4 AI 标注

- 结果页固定显示“AI 整理，请核对”。
- 导出的文件/分享内容带 AI 标识或元数据。
- 用户协议说明 AI 可能出错，以用户确认为准。
- 不删除微信平台要求的 AI 标识。

## 12. 指标与验证计划

### 12.1 核心指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 北极星指标 | 每周人均成功保存的日程/DDL 数 | 内测后设基线，beta 目标待定 |
| 识别成功率 | 识别成功并返回卡片的事项消息数 / 总事项消息数（转发 + 直接输入，经意图判断为含事项） | ≥90% |
| 意图判断准确率 | 正确判断是否含可记录事项的条数 / 总输入条数 | ≥90% |
| 事件级完整正确率 | 标题+时间+地点+类型全部正确的条数 / 总条数 | ≥80% |
| 时间准确率 | 时间正确条数 / 总条数 | ≥90% |
| 地点准确率 | 地点正确条数 / 有地点的条数 | ≥80% |
| 类型准确率 | 日程/DDL/任务分类正确条数 / 总条数 | ≥85% |
| 幻觉率 | 原文没有、结果新增的关键信息条数 / 总条数 | <5% |
| 确认率 | 确认保存数 / 识别成功数 | 观察值，目标待定 |
| 修改率 | 修改过至少一个字段的条数 / 确认条数 | ≤30% |
| 确认耗时 | 从打开确认页到保存的中位时长 | ≤10 秒/条 |
| 课表导入成功率 | 解析成功并保存的课程数 / 上传课程数 | ≥90% |
| 7 日留存 | 首周使用后 7 日内再次打开的用户比例 | 内测后设基线 |

### 12.2 上线前验证

| 验证 | 样本 | 通过标准 |
|---|---|---|
| 真机转发与直接输入 | 单条文字/图片/文件/链接/小程序卡片/位置；直接输入单条文字；2–10 条合并转发 | 两种入口都能收到完整内容；会话次日可找回；合并转发结论明确 |
| 直接输入与意图判断 | 10 条含事项的文字 + 10 条闲聊/问用法 | 含事项能生成卡片；闲聊不生成记录；误判可取消或手动创建 |
| 30 条通知抽取 | 30 条真实通知，≥3 条/类型；20 条留出集 | 见 5.3 门槛 |
| 课表导入 | 3 份 Excel、3 份文字 PDF、3 份扫描/图片、3 张手机拍照 | 课程数 ≥90%；字段 ≥80%；≤30 秒 |
| 确认流程 | 5 用户 × 10 条结果 | 中位 ≤10 秒；修改率 ≤30%；≥4/5 用户能完成 |
| Concierge/WoZ | 5–10 用户，每人 3–5 条真实通知 | ≥6/10 愿意连续用 3 次以上；≥3 人问“什么时候能用” |
| 订阅消息 | 真机授权、额度消耗、43101 错误 | 额度逻辑清楚；文案不承诺长期提醒 |

### 12.3 上线后观测

- 每周看：转发量、直接输入量、识别成功率、修改率、确认率、错误类型 Top 5、7 日留存。
- 每月看：课表导入成功率、订阅额度使用、反馈闭环、成本/条。
- 错误反馈按 P0/P1/P2 分类；P0 24 小时内处理。

## 13. 风险与开放问题

### 13.1 风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 单条转发收不到完整内容 | 中 | 致命 | 真机验证；失败则改用“复制 → 小程序” |
| 客服会话次日找不到 | 中 | 高 | 真机验证；提供永久入口；复访靠小程序 |
| 地点识别 <80% | 中高 | 高 | 地点二期或标“请确认” |
| 多事件拆分差 | 中 | 中 | 引导分次转发；确认页可删改 |
| 课表图片 OCR 差 | 高 | 中 | 先做 Excel/文字 PDF；图片延后 |
| 订阅额度不足 | 高 | 中 | 不承诺长期提醒；额度策略 + 小程序兜底 |
| 合规/备案延迟上线 | 中 | 高 | 提前准备隐私政策、备案、主体 |
| 模型成本超支 | 中 | 中 | 规则优先、缓存、降级小模型 |
| 确认流程摩擦 | 中 | 中 | A/B 测试“确认”与“高置信度直接存+撤销” |
| 样本不足导致误判 | 高 | 中 | 06 已标初稿；继续访谈/问卷；不把 n=2 当总体 |

### 13.2 开放问题

1. **确认流程。** 06 中 R1 明确“不愿意确认，最好直接存好”，R2 接受 20 秒内；访谈接受核对但担心准确率。v0.1 默认“确认后保存”，因为 AI 准确率未实测、误存成本高。等 5 用户 × 10 条结果测试后，再决定是否加“高置信度直接存 + 撤销”。这是 H9 的核心冲突，不能在 PRD 里直接写死。
2. **目标人群。** 高频记录者和低介入者的比例未知。06 的 2 份问卷不能回答。继续补 5–10 个访谈，优先找高频人群。
3. **H1/H3。** 固定时间段限制、手动提取耗时没有被直接测量。访谈下一轮追问“最近一次添加日程被卡在哪一步”“从收到通知到记完用了多久”。
4. **图片通知和图片课表是否进 v1。** 当前计划是文字通知 + Excel/文字 PDF；图片要等 OCR 准确率和真机测试。若用户大量转发截图，需要提前排期。
5. **订阅额度分配。** 06 访谈希望优先作业/考试；产品上按“作业截止 > 考试 > 会议活动”排序，但具体规则待测试。
6. **付费。** 免费 MVP；后续是否做学生订阅/买断，涉及支付、备案、退款、发票，单独评估。
7. **开发路径。** 先用 Coze + WorkBuddy 做抽取工作流和 HTML 原型验证，再写正式小程序；Coze 不是正式后端，WorkBuddy 不承载生产。
8. **主体。** 个人小程序不能认证、不能用微信支付、不能用 web-view；客服需要企业/组织主体。学生团队需要学校/公司挂靠或注册个体户。
9. **直接输入入口。** 用户会不会绕过转发、直接在客服会话输入？需要观察真实使用比例；如果占比高，可能需要优化输入提示或增加“记一下”快捷话术。

## 16. 附录

### 16.1 术语

- **日程**：需要在某个时间参加或发生的一次性事项。
- **DDL**：必须在某个时间前完成或提交的事项。
- **任务**：为了日程或 DDL 需要准备的行动，可勾选。
- **课程**：固定、重复的课表时间块。
- **Concierge/Wizard-of-Oz**：人工模拟 AI 服务，验证用户是否愿意用。
- **SDD**：Spec-Driven Development，先写清规格和边界，再让 AI 写代码。
