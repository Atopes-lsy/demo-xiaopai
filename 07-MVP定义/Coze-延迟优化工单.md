# Coze 工作流延迟优化工单（v3 → v3-opt）

> 交接对象：新窗口的 Claude / 开发同学。
>
> 目标：在**不牺牲抽取质量**的前提下，降低小排 Coze 工作流的端到端延迟。
>
> 原则：先测基线，再做优化；每次只改一个变量；用同一 7 条回归；没有数据不写结论。

## 0. 交接摘要

当前状态：

- 产品：小排，粘贴群消息/项目说明 → 抽取事项 → 日历排期。
- 工作流：`开始 → 意图分类 → parse_intent 代码节点 → 条件 → 抽取 LLM → normalize_extraction 代码节点 → 结束`。
- 当前 Prompt：v3，位于 [Coze-小排工作流提示词.md](Coze-小排工作流提示词.md) 第 4.2 节。

**E1b-1 结果（2026-10-19，未采用；不属于基线）**：在火山方舟直连、temp `0.1`、仅抽取 LLM 调用口径下，控制组 `max_tokens=2000` 与变量组 `1200` 各跑 7×3。C 主事项 18/21、V1 20/21；全部运行 median C 34947 ms / V1 36278 ms，非空输出 median C 36198 ms / V1 36418.5 ms，无中位数收益。但 `max_tokens` 没有实际约束生成：V1 19/21 次输出 >1200（最大 2909），C 也有 4/21 次 >2000（最大 3085），`finish_reason` 全为 `stop`。因此**这是操纵失败，不能做 max_tokens 归因**；质量差 20/21 vs 18/21 只能当运行噪声。生产维持 `2000`（未改动，无需回退），E1b-2（800）不执行。数据与偏差见 [v3.3/README.md](../06-研究发现/coze测试数据/v3/v3.3/README.md) 和 [E1b 工单第 9 节](Coze-E1b-参数控制工单.md#9-e1b-1-执行结果2026-10-19)。

本工单包含五个优化动作：

1. 参数控制（模型已确认为非推理，换模型项关闭）
2. 去掉独立意图 LLM 调用

4. 把确定性字段移到代码节点
5. 两级路由 / 级联

## 2. 测试协议

所有实验统一使用：

- 测试集：`06-研究发现/coze测试数据/v2/labels_result_v2.csv` 的 7 条（id 2–8）。
- 测试基准日：`2026-10-18 09:00 星期日`，时区 `Asia/Shanghai`。
- 每条至少跑 1 次；建议每条跑 3 次，记录所有延迟。
- 统计口径：准确率按同一轮预测评分；延迟记录 **median** 和 **p95**，不要只看平均值。

补充 B 暴露的问题不是延迟问题，必须先修：

1. **输入校验**：在抽取节点前断言 `raw_text` 非空；为空直接返回输入错误，不能进入抽取，也不能输出“无可记录事项”。补充 B 的 id 2 run1、id 6 run2、id 7 run3 都是这一类。

### T4 把确定性字段移到代码节点

**目标**

减少 LLM 输出 token 和重复规则，让代码做确定性校验。

**允许修改**

- [Coze-小排工作流提示词.md](Coze-小排工作流提示词.md) 中的 `normalize_extraction` 代码节点。
- 本地新增测试脚本/测试夹具（可选）。
- 如需改 LLM 输出 schema，必须先更新本文档和测试。

**不可破坏**

- event 的 `priority` 一律为 null。
- 非 task 的 `estimate_min` 一律为 null。
- 时间格式 `YYYY-MM-DD HH:mm` 校验。
- `dependencies` 只能引用同批 events 的 title。
- `needs_confirmation` 的现有阈值逻辑（confidence < 0.8、missing_fields 非空、ambiguity 非空）。

**建议顺序**

1. `needs_confirmation`：从 LLM 输出 schema 中移除，由代码计算（已有逻辑，确认不要重复）。
2. `missing_fields` 的基础缺失：
   - event 缺 `start_time` → 加 `start_time`；
   - deadline 缺 `deadline` → 加 `deadline`；
   - task 缺 `estimate_min` → 加 `estimate_min`；
   - 合并 LLM 的语义缺失（如“地点待通知”），不要覆盖。
3. `dependencies` 为空时由代码补 `[]`。
4. `confidence`：只有在确认下游不依赖 LLM 原始 confidence 时，才改为代码推导；否则保留。

**测试**

至少 5 个 fixture：

- 正常 event（有 start_time、location）；
- event 地点待通知（location 有粗层级，missing_fields 含 location）；
- deadline（有 deadline，priority 可为 null）；
- task（缺 estimate_min，应自动补 missing_fields）；
- unknown/invalid date（应被校验或标记）。

**验收标准**
