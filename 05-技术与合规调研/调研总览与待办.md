# 技术与合规调研总览

更新时间：2026-10-17
项目：课旁（课表 + 日程 + DDL，微信客服助手 + 小程序）

## 0. 一句话结论

技术侧真正卡脖子的不是“能不能做小程序”，而是三件事：

1. **微信客服能不能稳定接住“长按转发”的单条消息**（决定核心入口）；
2. **大模型从真实班群通知里抽时间/地点/类型，准确率能不能到 80%**（决定核心卖点）；
3. **课表文件（Excel/PDF/图片）导入的字段准确率**（决定冷启动体验）。

合规侧最优先的是：**用户主动转发的聊天内容属于个人信息**，必须在入口告知、最小化收集、限期删除，并准备好隐私政策和用户协议；如果使用大模型，还要确认模型供应商不训练、不留存，以及是否需要算法/生成式 AI 相关备案。

## 2. 现在就能做的三件事（不需要写代码）

1. **真机验证转发**：注册企业微信客服（仅人工），用另一个微信号分别转发单条文字、图片、文件、链接、小程序卡片、位置，以及 2–10 条合并转发；先看企业微信客户端展示，再决定是否搭最小回调抓 `sync_msg`。半天内出初步结论。
2. **收集 30 条真实通知**：从自己的班群/社团群/同学处收集，脱敏后按 `AI识别准确性测试方案.md` 的格式标注，先手工用大模型跑一遍，看时间/地点/类型准确率。
3. **确定主体**：要不要用企业主体？谁提供执照？微信认证约 300 元/年、微信支付需要企业主体，这些会影响上线时间。

## 3. 上线前 P0 清单（技术与合规）

- [ ] 单条文本转发真机通过，且 `sync_msg` 能拿到完整内容
- [ ] 合并转发 `merged_msg` 的 item 可解析，或明确只支持单条
- [ ] 会话找回验证通过（或明确回访只依赖小程序）
- [ ] 回调服务能验签、幂等、处理文本/图片；cursor 持久化，3 天窗口外有补偿
- [ ] `external_userid` 能与小程序 `openid` 绑定，或有一次性 token 兜底
- [ ] 订阅消息授权与额度机制按官方规则实现（单次最多 5 个模板），产品文案不承诺长期提醒
- [ ] AI 抽取在 30 条真实通知上达到事件级 80%、地点 80%、幻觉 < 5%
- [ ] 课表导入在 Excel/PDF/图片样本上达到课程数 90%、字段 80%
- [ ] 隐私政策、用户协议、用户隐私保护指引准备好
- [ ] 入口处明确告知“转发内容会到服务器识别”，提供删除入口
- [ ] 聊天原文默认不保存，结构化结果用户确认后才保存
- [ ] 小程序备案/ICP 备案、类目资质、域名 HTTPS 完成
- [ ] 确认大模型供应商不训练、不留存，并签数据处理协议
- [ ] 确认是否触发生成式 AI/算法备案义务
- [ ] 数据留存期限、权限、加密、日志、删除流程成文
- [ ] 未成年人用户处理方案（至少不主动面向未成年人营销）
- [ ] 客服入口、举报入口、错误反馈入口可用
