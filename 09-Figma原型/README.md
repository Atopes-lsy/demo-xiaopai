# 小排 · 可点击原型 v1

> 文件：[小排-HTML原型.html](小排-HTML原型.html) · 2026-10-19 · 单文件、无后端、示例数据

这个原型的唯一目标：在写小程序代码之前，用 2–3 人验证「粘贴 → 确认 → 自动排期 → 今日」是否讲得通。视觉是占位水平，不是最终设计稿。

## 怎么打开

- 直接双击 `小排-HTML原型.html`，在浏览器里打开；
- 或者在本目录运行 `python -m http.server 8765`，访问 <http://localhost:8765/小排-HTML原型.html>；
- 不需要联网。`file://` 下浏览器可能拦截「读取剪贴板」，直接用「试试示例」即可。

## 5 分钟走一遍

1. 首页点「粘贴一条消息或项目」；
2. 示例选「社团迎新筹备」→「开始整理」；
3. 确认页核对 7 个事项；找到「采购活动物料」的「预计 1 小时（估算）」和黄色「请确认」；
4. 点「确认并排期」；
5. 在排期页找到「排不下：发活动预告推文」，选一种处理（延长可支配时间 / 减少估时 / 拆任务 / 顺延 / 放弃）；
6. 拖动任一条任务右侧的把手，松手后出现「已锁定」；
7. 点「确认排期」回到今日，看到新增提示和新事项。

## 两个确认模式（H9 / F7 对比）

在右上「原型设置」或「我的 → 确认方式」切换：

- **先核对再保存（默认）**：所有事项都要过目，最稳，但多一步；
- **高置信度直接保存 + 撤销**：高置信度事项跳过确认，低置信度仍要求确认。

测试建议：

- 用「社团迎新筹备」跑默认模式，记录确认耗时、改了哪些字段；
- 用「比赛提交通知」测直接保存路径（两项都高置信度，会直接进排期）；
- 用「年级会通知」测低置信度路径（70%，结束时间和地点都待确认，仍会停确认页）；
- 同一个用户跑完两种模式后，再问「哪种更放心」「哪种更烦」，不要只问偏好。

## 其他可演示状态

- 「闲聊（应被拦截）」→ 没有可记录的事项；
- 「演示：解析失败」→ 解析失败；
- 「原型设置」→ 切换今日空状态 / 重置演示数据；
- 底部「日历 / 项目 / 我的」→ 排期落点、项目分组、计划偏好与隐私说明。

## 这个原型验证什么

**可以验证**

- 用户是否愿意把一段群消息/项目说明粘进来；
- 是否看懂任务、日程、DDL 的区分，以及时间、地点、截止的呈现；
- 是否接受 AI 给出的排期，以及「为什么排在这里」是否有帮助；
- 排不下时的五种处理里，用户会选哪个、为什么；
- 低置信度确认是否被理解，高置信度直接保存+撤销是否更顺畅；
- 拖拽/锁定是否符合直觉，用户会不会真的去改。

**不能验证**

- 真实识别准确率：确认页数据是预置的 mock，不是模型实时输出；
- 真实排期算法：时间块是预设/近似，没有做完整约束求解、冲突检测和跨天优化；
- 真实延迟：loading 用约 2 秒模拟；Coze 阶段全流程约 10–11 秒，不能拿这个原型谈性能；
- 微信订阅消息、审核、后端、多端同步；
- 真实用户留存或付费意愿。

## 测试时建议记录（配合 [2 人 pilot 记录表](../10-用户测试/pilot记录.md)）

- 从打开到保存用了多久；
- 确认页改了哪些字段、删了哪些卡；
- 是否触发「排不下」，选了哪个选项，为什么；
- 是否拖动/锁定，为什么；
- 哪一句解释没看懂，哪一步想退出；
- A/B 两种模式下，主观更放心/更烦的是哪种；
- 愿不愿意在真实场景再用一次，隐私顾虑是什么。

## 数据与隐私

- 示例里的「比赛提交通知」「年级会通知」参考了 Coze 测试的脱敏真实通知（id7、id4）；「社团迎新筹备」为合成场景；
- 原型不读取聊天记录、不后台监听剪贴板、不连接后端；刷新页面即恢复初始示例；
- 正式产品至少要保留：AI 整理标识、保存前核对、删除/导出入口、原文不长期保存的策略。
