# 课表 \+ 日程 \+ DDL 赛道：竞品与替代方案研究

**核心判断：**课表导入（Excel/PDF/图片/教务对接）在 2025–2026 年已是行业标配，不构成差异化；真正的机会在两个被所有竞品都没做好的缝隙——**从一条群聊/通知消息里提取「活动 \+ 时间 \+ 地点」三元组**，以及**固定课程 / 一次性日程 / DDL / 可勾任务四类对象的视觉分层**。超级课程表被广告与社区拖累（App Store 2\.9 分），滴答清单是通用工具、不懂课表语境且偏贵（¥138–168/年），学校官方小程序质量参差——“工具纯净 \+ AI 提取 \+ 三类分层”是一个真实但窗口期有限的位置。

# 执行摘要

**结论：**建议进入，但不要做“又一个课表 app”。以课表为日常入口，把群通知里的活动/DDL 用 AI 三元组提取作为核心钩子，第一版只闭合“班群通知 → 转发 → 确认 → 叠加到课表视图”这一条链路。

**形态结论（2026-10 更新）：**产品形态由独立 App 改为**微信客服助手 + 微信小程序**——即本文档“重审条件”中预判的那次转向，现已触发并采纳。理由不是转化率实测，而是能力边界倒推：目标用户的通知本来就在微信里，“长按转发”是微信内的原生动作，跨到外部 App 需要用户离开微信，链路天然更长。

**关键依据：**

1. 超级课程表对接 500–1500 所高校教务系统，但 App Store 评分仅 2\.9–3\.0，用户差评集中在开屏广告、震动广告、课表加载慢、社区低俗——存在明确的“工具纯净”换用户空间。

2. 滴答清单已支持微信转发给“滴答小助手”创建任务、智能识别日期、AI 语音拆多条，但**不识别地点**，也不区分日程与 DDL，且把课表当普通事件嵌入通用日历，没有节次/单双周/教学楼等课表语境。补充查明：它的“小助手”不是小程序，而是一个扫码添加的**微信好友**，公众号只负责对话式建任务。本项目采用同源的微信客服形态承接转发，但补上地点抽取与类型区分。

3. 新入局者（易课表、SleepDown、Meet、准点课表等）已把“图片/PDF/教务导入 \+ 预览确认”做成标配，SleepDown 明确“生成后先进入预览页再由你确认”——H6 和 H9 是入场券而非卖点。

4. 没有任何竞品做好“从一条班群通知消息里抽取活动名、时间、地点三元组，并自动判断它是日程还是 DDL”——这是 H2/H3/H7 的交集真空。

**主要约束：**微信生态能力边界已基本查清（见下“微信生态能力边界”专节）——单条转发待真机确认；合并转发在智能机器人场景取不到内容，但微信客服 API 已列出 `merged_msg`，能否解析待真机确认；订阅消息按一次性订阅设计，官方单次最多请求 5 个模板。AI 从自然语言识别地点和区分日程/DDL 的准确率仍未实测。

**下一步：**先做两件便宜的事——用 20–30 条真实班群通知手动跑大模型抽取，验证三元组准确率；访谈 5–10 个目标用户，确认“忘记记录群通知”是高频真痛。形态问题已定（微信客服 + 小程序），不再作为待决事项。

# 三个产品分野与建议站位

九个假设背后其实是三个不可避免的战略选择。下图把主要竞品放在“入口选择”和“课表冷启动路径”两个维度上，第三个分野（工具纯净 vs 社区/广告）用文字说明。

**分野一：课表入口 vs 任务入口。**学生每天主动打开的是课表，不是任务清单。任务/DDL 是叠加在课表上的层，而不是反过来。超级课程表和新入局者站在课表一侧，滴答站在任务一侧。**你应站在课表入口一侧**——这是学生每天的高频触点。

**分野二：教务系统深绑 vs 通用 AI 灵活解析。**超级课程表重投入对接 1500 所高校（强信任、高维护成本、合规风险）；SleepDown/Meet 走通用 AI 识别（低门槛、依赖模型、精度不稳定）。**你应走中间偏 AI 一侧**：主流教务对接做几个标杆学校即可，重点投在 AI 自然语言提取上——后者是 H7 的核心。

**分野三：工具纯净 vs 社区/广告变现。**超级课程表死于社区\+广告（2\.9 分、2019 年下架整改、2026 年缩短信渠道）；滴答走订阅制但贵。**你明确不做社区、不做开屏广告**——这是从超级课程表手里抢用户的最大理由。变现路径建议走学生负担得起的低价订阅或一次性买断，而非广告。

# 替代方案全景

你真正替代的不是某个 app，而是“不装任何 app，靠群公告 \+ 脑记”的状态。下表覆盖所有现实替代路径。

|替代方案|用户现在怎么用|为什么不满足|
|---|---|---|
|**纸质课表截图当壁纸 \+ 备忘录**|大量低年级学生|不能提醒、不能叠加日程、不能识别群通知|
|**手机系统日历 \+ 手动录**|一部分自律学生|要手动拆“周四下午 3 点 A301”；课表重复每周手动建|
|**滴答清单 / Todoist / Notion**|自律用户、考研党|不懂课表节次/单双周；不识别地点；付费；通用工具对学生过重|
|**超级课程表 / WakeUp**|老用户存量|广告、加载慢、社区噪音；WakeUp 被作业帮收购后评分崩|
|**学校官方教务小程序**|每校一个，质量参差|只看课表和成绩，不管日程/DDL/通知|
|**不装任何 app，靠群公告 \+ 脑记**|大多数学生的现状|**这才是你真正要替代的对象**——不是某个 app，而是“没工具可用”的状态|

# 微信生态能力边界（2026-10 新增）

形态改为微信客服 + 小程序后，原先基于 Android 系统分享的技术假设全部作废。本节是新形态下必须先划清的边界，它直接决定产品能承诺什么、不能承诺什么。

## 一、长按转发：单条待测，合并转发的结论要修正

- **单条消息转发：推断可用，待真机验证。** 用户长按一条消息转发给微信客服会话，官方没有专用消息类型或说明；可能按原类型到达，也可能以卡片/占位形式出现。微信客服 API 可接收文字、图片、语音、视频、文件、位置、链接、名片、小程序、菜单、事件和 `merged_msg`，但“接口支持该类型”不等于“转发后能拿到完整内容”。
  状态：**推断**，需真机抓 `sync_msg` 验证。
- **合并转发（多选多条）：官方已列 `merged_msg`，不能按“不可用”定稿。** 企业微信开发者社区有实测反馈：向智能机器人合并转发聊天记录，回调只收到一个标识，报文中不含内容，也没有可拉取内容的 media_id。但智能机器人和微信客服是不同接口；微信客服 API 官方文档已把 `merged_msg` 列为消息类型，含 title、item[]，item 为嵌套普通消息，支持范围未穷举。
  状态：**官证（消息类型存在）+ 待测（能否解析内容）**。

**对产品的约束：**在真机结果出来之前，不把“只能单条转发”写进产品承诺。测试结果分三种：

1. `merged_msg` 可解析 → 允许用户多选合并转发；
2. 只能拿到卡片/占位 → 只承诺单条转发，入口处讲清，多条时引导分次转发；
3. 单条也失败 → 核心入口改为“复制/粘贴 → 小程序”兜底。

**连带影响：**如果合并转发不可用，“从一条消息中抽出多个对象”就是多条目录入的唯一路径，权重从“锦上添花”上升到核心能力，直接支撑 H7；如果可用，则作为效率增强，不替代单条入口。

## 二、订阅消息：只能一次性订阅

教育类目下“在线教育”通常只能使用**一次性订阅**——用户每授权一次下发一条。官方当前单次调用最多请求 **5 个模板**（旧文档多为 3 个）；长期订阅只向政务民生、医疗、交通、金融、教育等**线下公共服务**类目开放，且模板库必须有对应模板。在线教育未被明确列入，但官方也未明文规定“只能一次性”；项目按最保守的一次性订阅设计。

机制细节：用户可勾选“总是保持以上选择，不再询问”，此后调用授权接口不再弹窗，但每次仍需用户主动点击才算攒下一次额度。额度可累加、永久有效，直到用完或在设置中关闭订阅时清零。

**对产品的约束：**不能承诺“设一次 DDL，到期自动提醒”这类长期提醒。注意真正的摩擦点不是“反复弹窗”——勾选保持后不再弹窗——而是**额度是消耗品，且只能靠用户主动点击来补**。产品上设计成“每次进入小程序顺手补额度”，并替用户决定把有限额度花在哪几件事上；额度耗尽的兜底是打开小程序看到的“本周 DDL”栏，而不是推送。

## 三、课表导入：聊天记录选文件比 App 更短

小程序可从微信聊天记录直接选择文件（Excel/PDF/JPG/PNG），也可拍照或从相册选图。用户的课表本来就在微信里流转，这条路比“从文件管理器找文件”更短——这是形态转向带来的净收益。教务系统对接仍需服务端代爬，小程序内嵌网页受业务域名限制。

## 四、主体资质与接待量

个人主体不能注册服务号，个人小程序也不能接入微信支付。本项目使用企业主体，服务号、微信客服、微信支付均可开；微信认证约 300 元/年。注意：后续若做付费订阅，支付经营类目需与营业执照经营范围匹配，存在不一致风险，需提前确认。

**接待量约束：**企业微信未认证时，微信客服**累计只能接待 100 位客户**；已认证则不限。对当前阶段的意义是——用户测试阶段 100 位绰绰有余，**不必提前花钱认证**，等确定要上线再办。

## 五、客服会话入口：没有自然发现路径

用户不需要加好友、不需要关注公众号、不需要装额外应用——但反过来说，**也没有任何“搜到它”的途径**。必须有人把客服链接或二维码递到用户面前，点击或扫码才进入会话。

对新项目而言，常规挂载位全部不可用：

- 公众号菜单——还没有公众号
- 小程序内的客服按钮——用户得先有小程序
- 微信搜一搜品牌官方区——需 A/B 级评级，新品牌达不到
- 支付凭证、视频号——不适用

**冷启动入口实际只剩：同学转发、班级群发二维码、海报。**这与目标场景（班级群）恰好重合，但意味着获客完全依赖转发，没有自然发现路径。
